# 0024. Profile data: equivalences, tables, numbering systems

- Status: Proposed
- Date: 2026-11-03

## Decision

- **`match.equivalences`** (new in the profile schema): `{id, map, policy, note}` folds applied to
  both sides *only for comparison*. Normalization steps fold silently; equivalences carry a policy.
  The gameplan's Arabic hamza/maqsura/marbuta notes, Arabizi ch/sh, Turkish circumflexes and the
  uz-Cyrl/tg Russian-keyboard letters all use them.
- **Data tables** (`profiles/tables/*.json`, `schemas/data-table.schema.json`) are generated by
  `pnpm tables` (`nabu tables`) from pinned sources, each with an SPDX licence:

  | Table | Source | Licence |
  |---|---|---|
  | `hk-tw-variants` | OpenCC ver.1.1.9 HKVariants + TWVariants | Apache-2.0 |
  | `hans-only` | OpenCC ver.1.1.9 STCharacters: S keys never used as T | Apache-2.0 |
  | `jyutping-ime` | Unihan 16.0 kCantonese plus the readings in kSMSZD2003Readings | Unicode-3.0 |

  Unihan gives mostly literary readings (行 has hang4/hang6/hong4 but no colloquial haang4). A
  richer Cantonese source, such as words.hk or CC-Canto, should replace or extend it before the
  `yue` course relies on the IME-homophone model.
- **Numbering systems** come from CLDR (`packages/i18n/src/generated/numbering-systems.json`).
- **Purity.** `compileProfile(profile, data)` takes tables, keyboards and numbering systems as an
  argument. Node loads them in `core-cli/src/load.ts`; the client will get them in bundles.
- Profile files are named `<lang>.<slug>.yaml` for id `<lang>/<slug>`. Policies marked
  `REVIEW` in a profile are proposals awaiting Ben's sign-off.
