# 0015. Schema bundling, branded and readonly TS types, Pydantic aliases

- Status: Proposed
- Date: 2026-11-03

## Context

§5.1 makes `schemas/` (JSON Schema 2020-12) the contract, with TS generated by
json-schema-to-typescript and Pydantic v2 by datamodel-code-generator. Several details the doc
leaves open turned out to matter:

- Both generators handle cross-file `$ref`s differently, and json-schema-to-typescript emits the
  same type once per file that references it.
- json-schema-to-typescript drops definitions that are reachable only through a `tsType`
  override (it skipped `RubySegment`).
- It has no readonly option, but §6.1's types are deeply readonly.
- datamodel-code-generator's default `RootModel` wrappers serialize as dict keys like
  `"root='jyutping'"` (Token.ruby/readings round-trip failed), and its enums produced a member
  named `strip` that shadows `str.strip` (pyright error).

## Decision

1. **One global type namespace.** `packages/schema/scripts/bundle.ts` merges every
   `*.schema.json` into one bundle whose `$defs` hold all named types. A name declared in two files
   is an error. Both generators read this bundle, so TS and Python names match.
2. `$id`s live under `https://nabu.invalid/schemas/v0/` (reserved TLD: never fetched).
3. Brands via `tsType`: `LangTag`, `OrthographyId`, `SchemeId`, `SenseId`, `KcId` are branded
   strings, as in §6.1.
4. **TaggedText.lang must carry a script** (`ScriptedLangTag`). §1 decision 3 said so; the
   schema now enforces it. Tags must be in canonical case.
5. A post-pass adds `readonly` to every property, index signature, array and tuple.
6. Pydantic: `--use-type-alias` (PEP 695 aliases instead of RootModel), `--enum-field-as-literal all`,
   frozen models, `extra="forbid"`.
7. A `MessageCatalog` schema covers `packages/i18n/messages/*.json` (see 0018).
8. CI runs `pnpm codegen:check` (regenerate, then `git diff --exit-code`).

## Consequences

- Python tests check that Pydantic and `jsonschema` agree on every example, valid and invalid.
  Hypothesis checks that the BCP 47 regex behaves the same under Rust regex (Pydantic) and
  Python `re`.
- Invariants a schema cannot express are listed in each schema's `$comment` and checked by tests
  for now; Phase 1 moves them into `@nabu/core`. They are: NFC, ruby and morph concatenation, and
  grapheme-safe token boundaries.
